### 执行顺序

1. 定位完整游戏、源码、运行目录、覆盖层仓库、现有构建/清单工具和相关测试。读取必要文件，避免全仓无目的扫描。核对实际远端、当前分支、历史基线和未提交变更；凭据仅从现有安全配置使用，不打印。
2. 输出成套文件清单，逐项列出来源、目标、用途和依赖；保留已有有效内容，只处理本次相关差异。遇到玩法或角色设计冲突，仅输出影响说明和建议，上报主对话。
3. 使用现有构建流程生成运行文件；在隔离目录或独立工作区组装候选，保留原始完整游戏和无关工作。检查源码引用、技能定义/注册、角色分类与素材路径，确认候选覆盖至匹配基准后无缺项。
4. 文件定稿后重建 manifest，复核最终文件与摘要、清单范围及过期条目。记录执行命令、退出结果和必要日志；后续修改文件须重新生成清单。
5. 在完整游戏环境执行需要引擎/设计文档的相关测试；在候选覆盖层验证清单、资源、依赖和构建一致性。有条件时验证实际角色加载及技能存在；未运行则明确待验证。隔离环境缺依赖时先查明正确运行位置，不伪造依赖、不跳过失败冒充通过。
6. 检查候选和暂存差异，排除凭据、依赖目录、缓存及临时文件；使用独立 `codex/` 分支，分支名按实际任务确定。按既有授权提交并推送核对后的 GitHub 远端，禁止强推、覆盖无关工作或删除历史。
7. 核实远端目标分支提交与本地提交一致，交付提交标识、配套清单、校验与测试证据、恢复基线和回滚步骤。不得把本地提交成功称为推送成功。
