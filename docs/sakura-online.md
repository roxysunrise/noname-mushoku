# Sakura Frp 联机（源码版）

2026-10-20：用户选择 Sakura Frp，本轮不打包、不覆盖现有 exe。

## 连接方式

Sakura Frp 是 TCP 转发服务，不是游戏大厅。保留原版 WebSocket 联机协议和标准身份玩法，以 TCP 隧道转发本机房间。无需在游戏中保存樱花账号、访问密钥或调用管理 API；Sakura 启动器负责登录及启动隧道。

1. 房主在 Sakura Frp 创建 TCP 隧道，本地 IP `127.0.0.1`、本地端口 `8080`，远程端口使用樱花分配值。
2. 房主运行同版游戏，在联机页面点击“启动服务器”，创建标准身份局。在樱花启动器开启对应隧道，确认日志显示 TCP 隧道启动成功。
3. 在房间点击“设置樱花公网地址”，填写日志中的 `节点域名:远程端口`，例如 `frp.example.com:23456`（仅为格式示例）。然后使用“分享房间”。已有公网地址会保留，可在房间内修改。
4. 朋友使用相同源码版本的游戏，在联机页面输入该地址，或 `ws://节点域名:远程端口`，点击连接。只有房主需要运行樱花启动器。
5. 至少两名玩家进入后，房主开始游戏。仍沿用原版空位 AI、选将、聊天、断线重连流程。

本地房间仅监听 `127.0.0.1:8080`，不使用 Electron 静态文件服务的 8089 端口。此路径仅支持 TCP + ws；不要选 UDP、HTTP 或填 wss。公网隧道域名及远程端口以自己的启动器日志为准。

官方配置依据：[Sakura Frp TCP 隧道示例](https://doc.natfrp.com/app/syncthing.html)。

## 八角色约束

- 所有客户端使用目前八人及原有 mt_ 技能，唯一角色池，不增加原角色或模式形态。
- 仅开放标准身份局，2 至 8 人。双将最多四人，禁将或其他禁用使人数不足时拒绝创建或开始。
- 创建、切换模式、修改房间设置、改变人数、开始、加入及重连均有配置检查；加入/重连要求八角色联机协议标记匹配，拒绝普通原版客户端。标记是兼容性声明，不是密码或防作弊认证。
- 原版身份选将把非主公候选从同一池中移除后分配，并从剩余池为 AI 补位，正常同版客户端不会重复选将。本轮未更改 identity.js、其他玩法源码或任何角色技能。
- 其他联机模式暂不开放，不连接公共大厅。
